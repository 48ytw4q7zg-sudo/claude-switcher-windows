# v0.6.11 — 第十二轮审计收口（提交窗口与写入门禁）

发布日期：2026-11-05
基线：v0.6.10（`d5794d5`）→ 本版
依据：GPT-6 第十二轮深度审计（固定 `56c0d0b`）

本轮六项 P0 中，P0-01 与 P0-02 是上一版留下的**真实漏洞**：
前者会让崩溃恢复留下「新账号库 + 旧快照」，后者会让迁移未收尾时仍能改写数据。

## 一、P0-01：迁移账号库提交窗口

| 问题 | 处理 |
| --- | --- |
| 崩溃落在「`tx.save` 成功」与「`store_committed=true` 落盘」之间，恢复器只回滚快照 | 账本新增 `store_commit_started`：**先写该标记再保存账号库**。恢复器以它判断「账号库可能已被改写」，不再依赖可能漏写的 `store_committed` |
| 账号库已损坏时，恢复器因读取失败而拒绝使用完好备份 | 改为直接按备份恢复，不以「当前库能否读出」为前提 |
| `fs::copy` 直接覆盖正式账号库，恢复途中断电会留下截断文件 | 改为「校验备份 → 同目录临时文件 → `sync_all` → 原子替换 → 回读校验」 |
| 运行时回滚重新加密写回，依赖密钥后端 | 改为优先使用原始备份文件 |

## 二、P0-02：迁移未收尾时仍可写数据

- 新增 `export::ensure_no_pending_migration()`，并在 `store::with_store()` **内部**调用：
  账号切换、创建/删除/重命名账号、快照捕获、Desktop 捕获/删除、普通加密导入全部被统一拦截。
  账本**不可读**同样拒绝——不能把「读不出来」当成「没有事务」。
- 恢复专用入口继续走 `with_store_transaction()`，不受该门禁阻塞。
- 启动恢复后若账本仍在，日志明确标记「待恢复：账号写操作已暂停」。
- `heal_desktop_switch()` 区分「文件不存在」与「读取失败」：后者报错而不是静默当作无事务。

## 三、P0-03：Desktop 失败永久卡死切换

原实现在**任何**错误路径都把账本写成 `FilesSwitched`。一次「目标快照不存在」的前置失败
就会留下 `original_existed=true + backup_path=None` 的账本，恢复器无法判断只能保留，
之后每次切换都被拒绝。

现在：
- 只有**确实完成文件切换**才推进到 `FilesSwitched`；
- 失败时按实际阶段决定：未动文件 → 清账本；已备份/已替换 → 保留供回滚。

## 四、P0-04：删除快照的跨事务竞争

原实现「删登记 → 释放锁 → `remove_dir_all`」，两步之间若导入重建了同 ID 快照，
会把新数据一起删掉。

现在整个删除持有 `with_store_transaction()`：
存在未收尾迁移/切换时直接拒绝 → 载入 → 把物理目录**原子改名**为唯一待删名 →
保存登记（失败则改回原名）→ 删除待删目录。

## 五、P0-05：防火墙核验覆盖不足

- 全局断网：`ActiveStore` 规则必须方向 `Outbound`、动作 `Block`、**程序/端口/地址全部为 Any**、
  且 `Profile = Any`，才算覆盖全部流量。限定 443 端口或只对 Domain 生效的规则不再算「已断网」。
- 应用隔离：同样补上端口过滤器、地址过滤器与 `Profile` 覆盖核验。
- 判定函数已在本机真实 PowerShell 上验证：无过滤器 → 全局成立；限定 RemotePort=443 → 不成立。

## 六、P0-06：未接入代理的即时兜底封锁

- 配置新增 `lockdown_on_uncovered`（默认开启）。
- 监控轮发现 **Uncovered** 的当轮就施加应用级出站隔离，不再等 `access_streak` 阈值。
- 独立的 `eguard-uncovered-lock.json` 记录兜底意图；接入恢复后清除。
- 只在 `Armed` 且未暂停时动作；`Unknown` / 未验证 TUN 一律不动手。
- 建立失败时明确报告 Degraded，不宣称已保护。
