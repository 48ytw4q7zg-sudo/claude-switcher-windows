# v0.7.7 发布说明（判据统一与并发收口）

> 日期：2026-11-06｜基线：v0.7.6 → **v0.7.7**
> 主题：**同一事实只能有一个判据，同一状态只能有一个事务持有者。**

## 0. 一句话结论

v0.7.6 修好了「系统修改要么是事务、要么是拒绝」。这一版修它的下一层：
**「同一件事的不同入口必须用同一套判据」**。7 个 P0 里最典型的三个是——
规则健康判定只查 4 项属性（被改成「只挡 TCP 443」也算健康）、「恢复默认目标」
绕过了布防校验（会把系统推到自动熔断边缘）、地区锁定的锁在实际修改前就释放了
（急救恢复的结果会被随后的迟到写入推翻）。

---

## 1. P0-01：规则健康判定不完整，判据还分叉了

**两个缺口**（都在 `quarantine_agent_for()`）：

**缺口 A** — 旧规则的 `$healthy` 只查 `Enabled / Action / 方向 / 程序` 四项。
一条被改成「只阻断 TCP 443」的旧规则会被判为健康、直接跳过修复；后面的完整
核验虽然发现不完整，却不再回头修。

**缺口 B** — 临时规则的 `ActiveStore` 检查只确认「存在」，没核对生效规则的属性。
本地规则与生效策略不同步时会过早认可。

**修复**（含 L-01）：抽出**唯一的** `Test-Rule` 函数，旧规则、临时规则、最终规则
共用一套判据，逐项核验：`Enabled`、`Action`、方向、程序绝对路径、协议与端口
不受限、地址不受限、Profile 覆盖全部配置档，以及 `ActiveStore` 里**对应规则的
属性一致**。替换改名后再核验一次，不通过如实报 `Partial`，不谎称完整。

## 2. P0-03：「恢复默认目标」绕过布防校验

`egate_save_targets()` 早就加了布防就绪校验，`egate_reset_targets()` 却漏了。
而 `builtin_targets()` 的 `expect_ips` / `expect_regions` **全是空的**，
Claude、Codex 还默认启用。

门禁已开、白名单正常时点一下「恢复默认」，配置就变成「已布防但没有有效白名单」
——下一轮拿到出口信息即判 `Fail`，到阈值后**熔断并结束用户正在用的桌面程序**。

**修复**：改走 `try_update`，校验与写盘在同一把配置锁内完成；门禁开启时拒绝
并说明如何处理。测试 `reset_targets_rejected_when_gate_is_armed` 验证
「被拒绝的操作不得清空白名单」。

## 3. P0-06：地区锁定的锁在实际修改前就释放

```rust
if apply {
    let _guard = acquire(...)?;   // ← if 块结束就释放
}
blocking(move || { /* 真正改时区 / Culture / Home Location */ }).await
```

`_guard` 在 `if` 块结束时就释放了，后面的 `blocking` 完全不在锁内。急救恢复
拿到锁还原环境后，迟到的地区锁定仍会把时区又写回去。

**修复**：锁放进 `blocking` 闭包里、紧挨着系统修改获取，并**持锁到回读核验
结束**；持锁后重新读配置确认目标未变；时区写入后回读比对，不符则不视为成功。

## 4. P0-05 / P0-07：意图事务与孤立清理

**P0-07**：事务号用 `秒级时间 + PID` ——同一进程同一秒内两次意图会得到同一个
ID，旧事务可能删掉新事务的意图。改用 UUID v4（测试连续创建 20 次全部唯一）。

**P0-07 后半**：`clear_uncovered_lock_if_txn` 在读不到事务号时「退化为按存在性
清理」。现在区分 `Current / Legacy / Unreadable`：**新格式缺事务号、旧格式、
读不到，一律拒绝自动清理**。

**P0-05**：`clear_uncovered_if_orphaned()` 原来只看「当前规则数量为零」。真实
交错顺序是——A 写意图（`Preparing`，规则还没建）→ A 等锁 → B 查到零条规则
→ B 删「孤立」意图 → A 拿锁建规则 ⇒ 规则在、归属它的意图没了。

**修复**：意图引入 `Preparing / Applied / Releasing` 阶段；孤立清理**持锁** +
阶段可清理 + 持锁后再查一次规则，三条都满足才删。`Preparing` 阶段绝不清理。

## 5. P0-02 / P0-04：判据被静默放宽

**P0-02**：`let _ = mark_initialized()` 把标记写入失败吞掉；`is_initialized()`
把「读取异常」折成 `false`（= 没初始化过）。两处叠加，已有用户仍可能在标记
读不出来时被当成首次安装，保护被默认值关掉。

**修复**：`Initialized::{Yes, No, Unknown}` 三态——`Unknown` **不得**放宽成
`No`；标记写入失败如实上报；配置读到了但标记写不进去时按「配置状态不可靠」处理。

**P0-04**：`uncovered_ready_state()` 查了规则属性和 `ActiveStore`，但没查
`effective_firewall_enabled()`。活动网络的防火墙 Profile 被关掉时，规则照样
存在、属性照样正确，却**没有实际拦住任何流量**。普通隔离执行器早就复核了这
一条，ready 判定却漏了——两处判据不一致。现在补齐，并区分「已关闭」与
「无法确认」。

## 6. P1

| 编号 | 修复 |
| --- | --- |
| P1-02 一键修复宽松配置 + 无锁 | 改严格配置读取（损坏/首次安装时**拒绝改系统**）；所有系统副作用（时区、IPv6）在同一把系统操作锁内执行，取不到锁就整体不执行 |
| P1-04 远程代理被当成可用 | 保镖与自动解除都不再对非回环代理 `Some((addr, true))`。**自动解除直接拒绝**（无法在不外发探测的前提下证明远程代理可用——而验证用的探测本身就会绕过保护，是循环论证）；保镖标注「接入正常但未验证」 |
| P1-05 严格防泄漏缺依赖校验 | 开启前检查 `egate_enabled` / `lockdown_on_uncovered` / 未暂停 / `Armed`，缺一项就拒绝，不让界面显示「开」而实际没生效 |
| P1-10 接入状态宽松配置 | `egate_access_status_inner` 改严格读取，配置损坏时报错而不是拿默认目标得出「接入正常」 |
| P1-11 计划任务查询吞错 | `task_exists` 改三态；查询失败**拒绝重新注册**（避免覆盖一个存在但读不到的任务） |

| P1-08 可信更新签名根 | 仍保持「不自动运行下载的安装包」 |
| P1-09 企业策略代理来源 | HKLM/组策略代理读取需真实域环境验证 |
| L-07 ACL 判定 | 同 P1-01 |
| L-10 / L-11 | 更多绕过语义表测与 VM 故障注入场景，随 P2-01 一起做 |

> **关于 P1-01 的判断**：审计指出「用当前进程令牌做可写性探针」在已提权的
> 上下文里会把安全目录也判成不安全。这个观察是对的。但把它改成 ACL 检查涉及
> 安全描述符解析与重解析点识别，写错比不写更危险——而且当前探针的**误判方向是
> 安全的那一侧**（宁可拒绝注册，也不注册不安全的任务）。所以本轮保留探针 +
> 黑名单的缓解，并在此明确记录其局限，留给独立的特权 helper 工作项一并解决。

## 11. 行为变化（升级须知）

1. **「恢复默认目标」在门禁开启时会被拒绝**，并提示如何处理（先关闭门禁或补齐白名单）。
2. **远程代理不再被默认视为可用**：自动解除兜底封锁时若代理是远程地址，会保守拒绝并保留封锁。
3. **一键修复在配置损坏/首次安装时会拒绝改系统环境**，而不是按默认值乱改。
4. **严格防泄漏开关需要前置条件**（门禁开启 + 兜底封锁启用 + 未暂停 + Armed），不满足时会明确说明缺什么。
5. **保镖计划任务注册前会先确认能否读到已有任务**，读不到就拒绝覆盖。
6. **内置目标的锚点类型在界面上只读**。
